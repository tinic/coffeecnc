Open finding: stale status can incorrectly confirm E-stop

The new settle and final checks treat a non-null StatusChannel::stat() as
fresh. That method intentionally returns the last cached EMC_STAT even when
the status write counter has stopped advancing; freshness is exposed
separately through link(). If the cached state is ESTOP and task stops
publishing, run() can time out and the new final path can still return
accepted from that old state. This changes a command failure into an
unsubstantiated confirmation.

Reported to Claude at 03:39 UTC; accepted. The final state descriptions and
confirmation must require live status. Planned regressions cover stale
ESTOP/OFF versus live ESTOP and, if practical, frozen-task simulation. The
fix and its evidence remain pending; passing tests below do not close it.
