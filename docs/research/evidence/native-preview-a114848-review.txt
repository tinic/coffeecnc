This is an unmerged prototype. The helper is not wired into the application.
This note records source-review findings, not a runtime qualification or an
exhaustive audit. Claude reported 18/18 portable tests (including 45 service
checks); those logs were not independently reviewed at this checkpoint.

The app service separates computation from the publisher and rejects completed
results from obsolete contexts. The helper uses public InterpBase, a separate
result descriptor and byte comparisons of input snapshots. The following issues
must be resolved before integration. Line numbers refer to the reviewed commit.

1. Guard side effects before interpreter read, not only before execute.
   preview_helper.cpp:651 calls interp->read(); refused_block follows at 662.
   LinuxCNC v2.9.4 read_semicolon invokes convert_comment during read for ;py,.
   A later refusal cannot undo Python execution. Pre-scan every snapshotted
   source, including external subroutines, before any interpreter use.
   Requested checks: a harmless marker remains absent for ;py, and (py,...)
   in main/external files, whether the containing code would execute or not.

2. Refuse names that cannot be represented by the private manifest.
   preview_engine.cpp:124 silently skips names containing '/' or '..', while
   program_watch.cpp:101 accepts such named O words. LinuxCNC find_ngc_file
   first tries the supplied path and expands it with wordexp(..., 0).
   Private cwd/search paths alone do not confine an absolute or expanded name.
   Require a strict basename set for calls and definitions before interpreter
   use. Requested checks: absolute, parent, tilde, dollar and glob names.

3. Separate the main snapshot from the subroutine namespace.
   preview_engine.cpp:147 names the main copy coffeecnc-program.ngc; 166 gives
   subs their ordinary <name>.ngc name. The write loop at 695 overwrites main
   when a real o<coffeecnc-program> subroutine is included.
   Requested check: that subroutine call retains the correct main program.

4. Bind the complete tool table to preview inputs.
   preview_engine.cpp:662 reads raw tools independently after input submission.
   status_publisher.cpp:12 compares only number/pocket/Z length/diameter.
   Raw X/Y offsets and the spindle table entry are absent from context equality,
   and a later read need not match the table used to create the context.
   Carry the accepted full table as input data; include all path-relevant fields
   in invalidation. Keep libtooldata on its sole publisher owner thread.
   This does not turn the existing two-pass stability check into an atomic read.

5. Bound unresolved calls and make snapshot work cancellable.
   preview_engine.cpp:127 deduplicates names by a linear scan. max_files at 157
   is checked only after a file resolves, so distinct missing calls can produce
   quadratic collection work and many more lookups than the stated file bound.
   Limit distinct names including missing resolutions before accumulation; use
   efficient deduplication and cancellation checks during scan/copy/comparison.
   Requested checks: bounded missing-name lookups and cancellation during compare.

Follow-up: result parser review, 2026-11-15 00:33 UTC

6. Stop parsing immediately when a numeric token is invalid.
   preview_wire.cpp:175 uses numbers = numbers && number(line, value).
   Once numbers is false, short-circuit evaluation leaves line unchanged.
   If another token remains, the loop keeps appending values without progress.
   This runs in the parent worker after the helper, outside its timeout; it can
   exhaust memory or prevent shutdown. Also reject non-finite coordinates and
   invalid line/tool numbers, and validate terminal records before publication.
   A result may retain only its complete, valid prefix.

   Independently reproduced with the unmodified preview_wire.cpp/.hpp exported
   from a114848, compiled with Apple clang 21, C++23, -O0 and the unchanged core
   panel-message headers. Retained harness: native-preview-wire-a114848-probe.cpp.
   Its operator new refuses single allocations above 1 MiB; alarm(1) additionally
   bounds runtime. The malformed case exceeds that allocation cap despite a
   tiny input. The valid control succeeds. This is a bounded parser reproduction,
   not a LinuxCNC/helper execution or a production memory measurement.

Follow-up: helper completion review, 2026-11-15 00:38 UTC

7. A terminal record is not a successful process exit.
   preview_engine.cpp:542 marks a result ready on `end ok` with no check of the
   observed child status. run_helper calls its SIGKILL cleanup before waitpid,
   even when both pipes reached EOF. Require both a valid complete result and
   an observed successful exit of the helper PID. Reap with a bound before group
   cleanup; distinguish exit N, signal, timeout, cancellation and cleanup kills.
   Valid prefix geometry can remain failed/partial on an abnormal exit.
   Requested fake-helper regressions: end ok followed by exit 7 or a signal must
   fail; normal completion, timeout, cancellation and cleanup remain distinct.
   This is a source-review finding; no native process reproduction was run here.
   Claude accepted it at 00:37. It remains open pending code and test evidence.
