Four findings in Claude's initial native Quit implementation 9cfbf9b are resolved:
1. Quit policy now requires live status before accepting idle/off placeholders.
2. Quit intent belongs to the request's Stage, not mutable session state. Current
   page/cancellation checks prevent a page ended during power-off from closing a
   replacement page or leaking intent into a later accepted request.
3. The page token travels through Runtime into the shell. Close waits for actual
   successful WebKit evaluation, not async submission. Failed delivery or a
   replaced page keeps the window open; callback lifetime uses outbox identity.
4. Dedicated power_off always sends EMC_TASK_STATE_OFF, never ESTOP_RESET, then
   waits for live off/E-stop status. This preserves an E-stop that arrives after
   the session's ON snapshot. Upstream OFF handling does not call emcAuxEstopOff:
   https://github.com/LinuxCNC/linuxcnc/blob/v2.9.4/src/emc/task/emctask.cc#L288
