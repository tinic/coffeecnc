Remaining finding sent to Claude

show_tools constructs a string with istreambuf_iterator before checking
in.bad(). That iterator can throw on a read failure even when the stream's
bad bit is not set. A minimal reproduction on playhouse2 opened /tmp as an
ifstream successfully, then threw:
  basic_filebuf::underflow error reading the file: Is a directory
  bad=0
PanelFeed::loop has no catch around source_.read(). A directory replacing the
tool-table path therefore escapes the intended unavailable/retry behavior.
Requested: handle read exceptions as a withheld table and add a regression
that recovers when the path becomes a readable file again.
