Open finding: data-directory guard uses a different INI grammar

The new run.sh guard reads [COFFEECNC] DATA_DIRECTORY with awk and compares
canonical paths with a directory boundary. It refuses an external root
before taking the host lock or creating the run directory. However, awk
requires the stripped whole section-header line to equal [COFFEECNC].
LinuxCNC's IniFile parser, used by the backend, accepts trailing text after
that header. Consequently a valid header can bypass this guard.

Parser-only reproduction on playhouse2, using temporary INI files and the
installed /usr/bin/inivar; no LinuxCNC instance was launched:

  [COFFEECNC] # settings
  DATA_DIRECTORY = /tmp/coffeecnc-parser-outside

  inivar -ini <file> -sec COFFEECNC -var DATA_DIRECTORY
    exit 0, stdout /tmp/coffeecnc-parser-outside
  The guard's exact awk expression
    exit 0, empty stdout

The same mismatch occurs with '[COFFEECNC] ; settings' and a tab before
the '# settings' suffix. The plain header agrees in both readers. Lowercase
section/key names are absent for both readers in this experiment.
The named outside directory was never created.

Sent to Claude on AgentNet at 04:18 UTC and acknowledged: use LinuxCNC's
reader instead of a separate awk grammar, and add suffix regressions.
Missing DATA_DIRECTORY must remain valid for XDG-based configurations such
as the current G0759. Missing utility, unreadable input and absent optional
key need appropriate distinct handling. The fix is not yet reviewed.
