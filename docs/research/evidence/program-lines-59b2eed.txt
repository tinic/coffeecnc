Observed defect: close/open clears LinuxCNC's line counters. A subsequent
E-stop while idle restores the earlier run's currentLine. MDI after a valid
AUTO run can also change the task counters. Passing these through can show
an old line beside a new file.

The mapper now attributes counters only after observing a fresh AUTO run of
the loaded revision, with a changed counter or motion/dwell/tool-change
activity. Manual/MDI activity clears attribution. The first AUTO idle sample
after execution supplies retained end values; later idle samples do not
change them. The UI displays live line progress only during fresh active
AUTO execution; otherwise it shows a static file line count.

Limits: a run missed between publisher samples leaves unknown lines at 0.
External MDI that starts and ends between samples can go unobserved. Motion
left over from before a newly observed AUTO run could establish attribution
one block early; no such sequence was observed. Attribution is an observed
state rule, not an interpreter-provided program identity attached to a line.

The final timing fix dates local acquisition before the read. A thread
preempted after acquiring a status cannot publish that sample with a new,
post-reload timestamp. The consumer regression injects a delayed publication;
it does not exercise reader preemption, and the reader has no unit hook.
This timestamp is not LinuxCNC's publication time. Shared-buffer data can
already be older; writer-heartbeat checks remain separate, and the two-pass
tool-table check establishes sampled stability rather than atomicity.

The 400 measured status calls took median 28 us, p99 43 us, max 45 us in this
simulation run. These are measurements, not acquisition deadline guarantees.
