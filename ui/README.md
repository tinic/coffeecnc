# CoffeeCNC operator panel

Vue 3 / TypeScript panel using the [original CoffeeCNC concept](../docs/concepts/coffeecnc-mill.html) as its visual base. The browser simulator is separate from LinuxCNC and is labeled throughout the interface.

```sh
npm ci
npm run dev
```

Open `http://127.0.0.1:5174/?scene=running&tab=program&theme=light`. Use `theme=dark` for the other theme. `tab=manual` and `tab=tools` select the other workspaces; view changes do not request a machine mode change. The default view of a program is its toolpath, with Code and Split available explicitly.

```sh
npm run check
npm run build
```

The 339 tests cover the protocol fixtures, simulator, interpreter, store, camera, units, jog lease, STEP mesh validation, model placement/import lifetime, parametric tool envelopes, default inheritance tool-model editor behavior, loaded-tool identity/position gating, capability-aware jog/execution controls, protocol-mismatch handling, program unload/reload identity, partial text/directory presentation and preview diagnostics. The shared native message fixture has 29 cases checked against TypeScript and the C++ encoders, including null versus zero/false and partial snapshots. Preview regressions cover changed initial position, inherited motion mode and prepared tool, while retaining a stable context during execution. Work-offset component tests cover explicit availability, real zeros, older complete tables, stale/down readings, malformed rows and operator-triggered selection. Transport tests cover browser simulation, a missing or malformed native handler, and native request/reply delivery. Held-jog regressions cover stale/silent status, power loss, E-stop, busy/homing state, homed-space changes, local answer timeout and synchronous refusal. An interrupted gesture requires a new press after recovery. The visual correction was also exercised in the browser: cycle start, manual tool acknowledgment, hold/resume, Stop, view switching while paused, and a held jog followed by release and zero feed. These are simulator checks, not machine validation.

## Touch operation and stable feedback

In Manual, tap an X, Y or Z work-coordinate value, letter or target icon to open touch-off. The keypad starts with that coordinate in the selected display units. The first digit replaces it; **Zero** explicitly chooses zero. Only **Set G54 X** (or the corresponding active system/axis) submits the offset change. Accepting the initial value preserves its unrounded millimeter value. Machine position and distance-to-go remain read-only; changing units, workspace, connection, coordinate system or command availability cancels an open draft. [Current-value keypad screenshot](screenshots/coordinate-touch-off.png) uses the browser display fixture.

Touching a numeric text field opens a shared keypad for spindle RPM, tool numbers and dimensions, tool-model geometry, and STEP placement. **Use value** changes only that field; Apply, Run or Save remains a separate action. Touch-off uses the same keypad with its explicit offset-setting action. Physical keyboard entry remains available. The keypad rejects non-finite values, fractions in integer fields, and drafts whose field was removed, disabled or changed. Changing the connection identity, display units or workspace closes the draft.

Numeric fields use `inputmode=none`, become read-only before touch focus, and prevent the default touch action. The keypad opens on release inside the field. Its controls require a new press, preventing the opening gesture or compatibility click from deleting a digit or activating a key. Native hover tooltips are suppressed during touch use; their descriptions remain available to accessibility tools. Older WebKitGTK has a [known input-mode bug](https://github.com/WebKit/WebKit/commit/70da7470a97f93585864227eb629f71dfd13f488), so the hint alone is insufficient. Native GNOME keyboard suppression still requires checking on the mill; browser touch emulation does not establish it.

Power menus close after both an accepted result and a fresh matching machine state. The message band, DRO markers, jog restrictions and MDI restrictions always reserve their space. Informational messages cannot erase an undismissed error. Jog buttons are 68 × 68 pixels, with step choices alongside them. MDI expands above the bottom-aligned work coordinate selector, and the bottom identity footer is removed. XYZ labels use exactly the same font, size and weight as the values; the coordinate rows and mm/in buttons share a vertical center even when homing status is present. Production-browser checks passed at 1600 × 900 and 1280 × 800 in light/dark themes, including unchanged control positions during homing and long errors. See the [follow-up record](../docs/research/evidence/operator-touch-followup-2026-11-15.txt), [compact layout](screenshots/operator-refined-1280x800-dark.png), and [inch layout](screenshots/operator-refined-inch.png).

Live readouts use tabular numerals, with monospaced digits and reserved space for machine feedback, coordinates, overrides, feed and counters. Measured RPM keeps its unit in place as the digit count changes; stale and unavailable feedback retain the same space. Coordinate values align at the right edge and keep the same horizontal position between Manual and Machine. The readout fixture passed 16 layout checks across both workspaces, 1280 × 800 dark and 1600 × 900 light, with short, wide, stale and missing values. See [measurements and limits](../docs/research/evidence/live-readouts-2026-11-15.txt), [Manual stress capture](screenshots/stable-readouts-manual.png), and [Machine stress capture](screenshots/stable-readouts-program.png). These captures use deliberately extreme fabricated values, not a connected machine.

The display unit selector offers explicit **mm** and **in** buttons. Native-unit jog increments retain the machine configuration; alternate-unit choices use round values bounded by the configured maximum. Switching units releases a held jog and requires a new step selection when the old distance is absent from the new choices. Requests retain canonical millimeters, and display-unit changes do not issue G20/G21.

The browser preview shows toolpaths, an optional STEP part layer and a configured loaded-tool envelope. The native GTK/WebKit executable now runs this panel against LinuxCNC simulation; interpreter preview, STEP import, the stock/path overlay and the tool-model editor have native simulation checks. Stock removal and hardware operation remain separate increments. Tool sequence labels come from interpreter segments and the tool table; they are not assumed CAM operations or claims of measurement. Fonts are bundled under `public/fonts/` with their licenses. In Machine, use **Attach STEP model → Choose STEP file…**. The simulator also offers an SM-101 sample, explicitly labeled as not paired with the demo NC program. Import runs in a dedicated worker; Three.js renders a translucent mesh beneath the toolpath using the same orbit/pan/zoom camera. The importer and renderer load on demand from local assets. WebGL 2 is required for the optional part/tool meshes; the 2D toolpath remains available without it.

The model starts at the current work origin with placement marked unconfirmed. Edit XYZ translations in millimeters and XYZ rotations in degrees, then **Apply placement**; this changes only the display. Visibility and opacity are independent of the toolpath. Registration is captured against the program revision, WCS, G5x, G92 and XY rotation; changed work coordinates hide the model until placement is reviewed. Reloading/changing the program removes it. Attachments are page-local and are not saved across page reloads.

Imports are limited to 25 MB, 500,000 triangles and 800,000 vertices, with a 30-second deadline and cancellation. These are input/output limits, not a hard WASM heap quota. Failure preserves the previous attachment. Run `npm run check:step` to exercise the real WASM importer against all 29 repository STEP samples, including centimetre/inch source-unit checks against documented physical sizes. See [the library comparison and integration boundary](../docs/research/step-preview.md) and [third-party notices](THIRD_PARTY.md).

In Tools, **Model defaults** configures nominal proportions for seven tool families. **Set model** on a row selects a family and optional absolute dimension overrides, with a live WebGL 2 envelope preview. Browser demonstration defaults persist in browser storage, with page-local tool assignments. Native sessions never read or write that browser key. A backend advertising tool-model storage supplies settings for its explicit machine identity; older backends remain session-only. Native assignments restore only against a matching live tool-table row, and missing/stale rows never delete the saved catalog. The editor supports mm/inch display, keeps physical dimensions independent of controller Z offsets, and does not issue controller commands. Production-browser checks covered saved defaults across reload, diameter scaling, overrides, the 1280 × 800 layout and a narrower viewport. See [the geometry and storage contract](../docs/design/tool-models.md). The Machine preview places the configured loaded tool at its reported tip and shares the STEP camera. Browser checks covered tool visibility, combined STEP/tool rendering and motion followed by feed hold at 1280 × 800. The panel waits for a new settings snapshot and accepted save result before closing the editor. Failure retains the draft; timeout does not imply cancellation. A corrupt or unsupported document disables saving. The native writer and this panel pass editor save and full LinuxCNC/application restart checks; see the [integration review](../docs/research/evidence/native-tool-models-06ae603-review.txt).

### Quitting the application

Open the machine-state menu at the upper right and choose **Quit CoffeeCNC…**.
The confirmation explains that LinuxCNC shuts down and the machine switches
off. Cancel is focused first. A running or paused program must be stopped
before quitting; machine off and E-stop do not prevent an idle quit.

The action needs a live connection and a backend advertising `quit_supported`.
Older backends show an unavailable explanation and receive no quit command.
The browser simulator reports a simulated quit and stays open. Native request
acceptance is not reported as completed shutdown. See the
[shutdown contract](../protocol/README.md#application-shutdown).
